# Beitragen zum Projekt

Vielen Dank für Ihr Interesse am hsamanafahrzeug Projekt! Wir freuen uns über Beiträge aus der Community.

## Wie Sie beitragen können

Es gibt viele Möglichkeiten, zum Projekt beizutragen:
- **Code beitragen**: Neue Features implementieren oder Bugs beheben
- **Dokumentation verbessern**: Wiki-Seiten erweitern oder aktualisieren
- **Bugs melden**: Probleme im Issue-Tracker melden
- **Features vorschlagen**: Neue Ideen einbringen

## Erste Schritte

### 1. Repository forken

```bash
# Fork auf GitHub erstellen
# Dann Ihren Fork klonen
git clone https://github.com/IHR-USERNAME/hsamanafahrzeug.git
cd hsamanafahrzeug
```

### 2. Branch erstellen

```bash
# Neuen Branch für Ihre Änderungen erstellen
git checkout -b feature/mein-neues-feature
```

### 3. Änderungen vornehmen

- Schreiben Sie klaren, gut dokumentierten Code
- Folgen Sie den Coding-Standards des Projekts
- Testen Sie Ihre Änderungen gründlich

### 4. Commit und Push

```bash
# Änderungen stagen
git add .

# Commit mit aussagekräftiger Nachricht
git commit -m "Beschreibung der Änderungen"

# Zu Ihrem Fork pushen
git push origin feature/mein-neues-feature
```

### 5. Pull Request erstellen

- Gehen Sie zu Ihrem Fork auf GitHub
- Klicken Sie auf "Pull Request"
- Beschreiben Sie Ihre Änderungen detailliert

## Coding-Richtlinien

### Code-Stil
- Verwenden Sie aussagekräftige Variablen- und Funktionsnamen
- Kommentieren Sie komplexen Code
- Halten Sie Funktionen klein und fokussiert

### Commit-Nachrichten
- Verwenden Sie klare, beschreibende Commit-Nachrichten
- Nutzen Sie die Gegenwartsform ("Füge Feature hinzu" nicht "Feature hinzugefügt")
- Referenzieren Sie relevante Issues (#123)

### Dokumentation
- Aktualisieren Sie die Dokumentation bei Änderungen
- Fügen Sie Beispiele hinzu, wo sinnvoll
- Halten Sie die Wiki-Seiten aktuell

## Issue-Richtlinien

### Bug-Reports
Bei Bug-Reports sollten Sie folgendes angeben:
- Beschreibung des Problems
- Schritte zur Reproduktion
- Erwartetes Verhalten
- Tatsächliches Verhalten
- Systemumgebung

### Feature-Requests
Bei Feature-Vorschlägen:
- Beschreiben Sie den Use-Case
- Erklären Sie den erwarteten Nutzen
- Schlagen Sie mögliche Implementierungen vor

## Review-Prozess

1. **Automatische Checks**: Pull Requests werden automatisch überprüft
2. **Code Review**: Maintainer überprüfen den Code
3. **Feedback**: Ggf. werden Änderungen angefordert
4. **Merge**: Nach Genehmigung wird der PR gemerged

## Community-Richtlinien

- Seien Sie respektvoll und konstruktiv
- Helfen Sie anderen Community-Mitgliedern
- Folgen Sie dem [Code of Conduct](Code-of-Conduct.md)

## Fragen?

Wenn Sie Fragen haben:
- Öffnen Sie eine Discussion auf GitHub
- Kontaktieren Sie die Maintainer
- Schauen Sie in die [FAQ](FAQ.md)

## Lizenz

Mit Ihrem Beitrag stimmen Sie zu, dass Ihr Code unter der Projektlizenz veröffentlicht wird.

## Danksagung

Alle Beiträge werden geschätzt! Vielen Dank, dass Sie helfen, hsamanafahrzeug zu verbessern.
